# 유입 10배 계획 (2026-07-20 작성)

목표: 하루 110명 → 1,100명. 오늘 GSC·GA·사이트맵·소셜 실적을 다 열어보고 나온 진단과 처방이다.

## 1. 990명을 어디서 데려오나

먼저 산수부터. 지금 구성은 이렇다.

| 채널 | 현재 | 10배 하려면 |
|---|---|---|
| 네이버 | 약 86명/일 (78%) | 860명 |
| 구글 | 약 1명/일 (3개월 67클릭) | 10명 |
| 직접·기타 | 약 23명/일 | 230명 |

**구글을 50배로 키워도 50명이다.** 오늘 하루 구글 데이터만 파고들었지만, 산수로 보면 부족한 990명의 대부분은 네이버에서 와야 한다. 이건 계획의 전제다.

다만 구글 쪽 작업이 네이버에 그대로 먹히는 부분이 있다. 페이지가 존재하고, 제목이 검색어와 맞고, 내부 링크로 이어져 있는 것은 두 엔진 모두에 필요하다. 아래 처방은 그 교집합을 먼저 친다.

## 2. 진단: 재고의 95%가 죽어 있다

사이트맵에 URL이 1,396개인데 그중 **1,330개가 매치 페이지**다. 그리고 GSC가 3개월간 노출을 기록한 URL은 **40개뿐이고, 그 40개에 매치 페이지는 하나도 없다.**

이유는 세 가지가 겹쳤다.

**고아 페이지.** 홈에서 매치 페이지로 가는 링크가 18개, 리그 페이지에서 5개다. 나머지 1,300개는 사이트맵에만 있다. 검색엔진은 사이트맵을 색인 보장으로 취급하지 않는다. 링크로 도달할 수 없는 페이지는 크롤 우선순위가 바닥이다.

**수명이 하루다.** 매치 페이지는 특정 날짜의 특정 경기다. 경기가 끝나면 그 URL을 찾을 이유가 사라진다. 색인이 되더라도 수요가 하루짜리라 누적이 안 된다. 페이지를 1,330개 쌓았는데 상시 수요가 붙는 페이지는 0개인 셈이다.

**정면 경쟁.** "다저스 양키스 중계"를 검색하면 네이버 스포츠가 같은 데이터를 더 빨리, 더 크게 보여준다. 우리가 이길 수 있는 자리가 아니다.

정리하면 페이지를 많이 만든 게 문제가 아니라, **수명이 하루짜리인 것을 고아 상태로, 이길 수 없는 자리에** 만든 게 문제다.

## 2-1. 경쟁 사이트 대조 (kicktalk.xyz)

같은 분야 사이트가 애드센스를 달고 있어서 실제로 뜯어봤다. 결과가 우리 가정을 뒤집는다.

| | kicktalk.xyz | 한해설 |
|---|---|---|
| 사이트맵 URL | 161개 | 1,396개 |
| 엔티티 페이지 | 국가·팀 48개 | 없음 |
| 에디토리얼 | 6편 | 20편 |
| 애드센스 | 승인됨 (`ca-pub-1649642792791162`) | 4차 거절 |

**페이지 수도 글 수도 우리가 많은데 얘가 통과했다.** 그러니 거절 사유는 "양이 부족해서"가 아니다.

내용을 비교하면 갈리는 지점이 보인다. kicktalk의 팀 페이지는 1,171자인데 FIFA 랭킹, 조 편성, 공격·수비·조직력·경험 점수, 플레이 스타일 서술, 감독 이력, 선수단 27명이 들어 있다. 팀마다 실제로 다른 내용이다.

우리 매치 페이지는 1,784자로 더 긴데 이런 식이다.

```
프리미어리그 아스날 vs 번리 경기는 쿠팡플레이에서 중계됩니다.
해당 중계는 한국어 해설로 제공됩니다.
경기 미리보기
프리미어리그 아스날 vs 번리 경기가 2026-05-19 04:00에 쿠팡플레이에서 한국어 해설로 중계됩니다.
아스날는 시즌 0승 0패 상태입니다.
```

같은 문장을 변수만 바꿔 두 번 쓰고, 전적이 0승 0패로 비어 있고, 조사도 틀렸다. 글자 수는 채웠지만 사람에게 주는 정보는 세 줄이다. **그리고 이런 페이지가 1,330개로 사이트의 대다수를 차지한다.**

애드센스는 사이트 전체를 본다. 에디토리얼 20편을 더 써도 1,330개의 템플릿 페이지가 평균을 끌어내린다. 4차 거절 이후 우리가 잡은 처방(사람이 쓴 글을 늘린다)은 방향이 틀렸을 가능성이 크다. 늘려야 할 게 아니라 **줄이거나 채워야 할 것**이 문제였다.

이 대조는 아래 처방 A와 D가 유입뿐 아니라 애드센스에도 그대로 작용한다는 뜻이다. 하나를 고치면 둘이 같이 움직인다.

## 3. 처방

### A. 팀 페이지를 만든다 (제일 큼)

데이터에 고유 팀이 **349개**, 리그가 35개 있다. 지금 팀 단위 페이지는 하나도 없다.

팀은 매치와 달리 **상시 엔티티**다. "두산 중계", "다저스 경기 일정", "한화 경기 어디서"는 시즌 내내 검색된다. GSC에도 이미 흔적이 있다. `두산 한화 중계`가 28위로 잡혔고, `한화 순위`·`두산 순위`·`키움 순위`·`삼성 순위`가 각각 노출되고 있다. 팀 이름으로 오는 수요가 실재한다는 뜻이다.

한 페이지에 들어갈 것은 이미 다 가지고 있다. 다음 경기 일정과 중계처, 한국어 해설 여부, 최근 전적, 순위, 하이라이트 영상, 라인업. 변수만 갈아끼운 껍데기가 아니라 팀마다 내용이 실제로 다르다.

`/team/[slug]` 349개. 매치 페이지 1,330개보다 적지만, **수명이 시즌 내내**라 누적된다.

### B. "[리그] 중계" 자리를 제대로 친다

GSC 검색어를 보면 이 패턴이 계속 우리를 스친다.

| 검색어 | 노출 | 순위 |
|---|---|---|
| 세리에a중계 | 10 | 36.8 |
| 유로파리그중계 | 7 | 22 |
| 분데스리가중계 | 7 | 54.3 |
| kbo중계 | 5 | 71 |
| 라리가중계 / kbl 중계 / k리그2 중계 / 해축중계 | 각 1 | 35~80 |

전부 20~80위다. 노출은 되는데 아무도 못 본다. 그리고 이건 순위표 검색과 달리 **네이버가 독점하지 않은 자리**다. "어디서 보나"는 질문이라 우리 데이터가 정답에 더 가깝다.

리그 페이지 15개를 이 검색어 모양에 맞춰 다시 짠다. 제목, 첫 화면, 구조화 데이터를 "이 리그를 어디서 보나"에 정렬한다.

### C. 허브와 스포크를 잇는다

지금은 허브(리그·플랫폼)에서 스포크(매치)로 가는 링크가 5개뿐이다. 팀 페이지가 생기면 계층이 이렇게 된다.

```
홈 → 리그(35) → 팀(349) → 매치(1,330)
     플랫폼(10) ↗
```

팀 페이지가 매치 페이지를 링크하면 1,330개가 처음으로 고아를 벗어난다. 반대로 매치 페이지는 양 팀 페이지로 링크를 돌려보낸다.

### D. 매치 페이지를 정리한다

과거 경기는 색인에서 뺀다. 지금도 얇은 매치는 noindex지만 기준을 날짜로 강화한다. 크롤 예산을 상시 수요가 있는 팀·리그 페이지로 돌리는 게 목적이다.

경기 당일과 직전 며칠만 색인 대상으로 두고, 끝난 경기는 팀 페이지의 전적 기록으로 흡수한다.

### E. 네이버 축은 데이터 없이 못 움직인다

유입의 78%인데 **네이버 서치어드바이저를 한 번도 안 봤다.** 어떤 검색어로 오는지, 어느 페이지가 먹는지, 순위가 몇 위인지 전혀 모른다. 구글 데이터로 세운 위 계획이 네이버에서도 맞는지 확인이 안 된 상태다.

A~D를 진행하되, 네이버 데이터를 확보하면 우선순위를 다시 잡는다. 여기가 볼륨의 8할이다.

## 4. 순서와 기대치

1. 팀 페이지 (A) + 내부 링크 (C) 를 같이 낸다. 둘은 한 덩어리다.
2. 리그 페이지 재정렬 (B).
3. 매치 색인 정리 (D).
4. 네이버 서치어드바이저 확인 (E). 사람 손이 필요하다.

**기간은 최소 2~3개월이다.** 색인에 몇 주, 순위가 자리 잡는 데 다시 몇 주가 걸린다. 팀 페이지를 오늘 올려도 이번 달 숫자는 안 바뀐다.

**그리고 10배가 보장되지 않는다.** 정직하게 말하면 349개 팀 페이지가 전부 상위에 올라도 팀당 하루 2~3명이면 700~1,000명이다. 산술적으로는 닿지만, 전부 상위에 오르는 일은 없다. 절반이 자리를 잡아도 300~500명이고 그것만 해도 지금의 3~5배다.

10배가 안 되더라도 3배는 현실적이고, 그 과정에서 만든 팀 페이지는 계속 남는다. 매치 페이지 1,330개와 달리 썩지 않는다.
